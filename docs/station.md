# Станция

[English](station.en.md) · [Документация](README.md)

## Запуск

Нужен Python 3; сторонние библиотеки не требуются. Из корня репозитория выполните:

```sh
python3 station/server.py
```

Откройте `http://127.0.0.1:8321`. По умолчанию сервер слушает только этот компьютер. Остановить его можно `Ctrl+C`.

Порт можно изменить переменной `FVZ_PORT`, а путь к SQLite-базе — `FVZ_DB`. По умолчанию база создаётся в `station/data/station.sqlite`; сохраните её, если хотите сохранить журнал и раскладки дашбордов.

Чтобы плату пустить по Wi‑Fi, страница должна слушать адрес сети: `FVZ_HOST=0.0.0.0`. Тогда строку может прислать любое устройство в этой сети. Пароля у входа нет. USB и Bluetooth этого не требуют.

## Показания

Строку можно добавить вручную в форме на странице или отправить JSON-запросом `POST /api/readings`. Сервер принимает один объект, массив объектов или объект с массивом `readings`. У каждой строки должны быть `sensor_id`, `quantity`, `unit` и числовое `value`; `node_id` по умолчанию равен `station`. Необязательные поля: `observed_at`, `experiment`, `note`.

Поддерживаемые величины и единицы:

| `quantity` | `unit` |
| --- | --- |
| `air_temperature` | `celsius` |
| `relative_humidity` | `percent_rh` |
| `reference_temperature` | `celsius` |

Другие API-адреса обслуживают состояние страницы, журнал и настройки дашбордов; их реализация находится в `station/server.py`.

## Запись с платы

Прошивка лежит в `firmware/fermozavr_recorder/`. В одной сборке включён один путь: USB, Wi‑Fi или Bluetooth. Путь задаётся `FVZ_LINK` в `config.example.h`. Свою сеть и адрес страницы пишут в копию `config.h` рядом со скетчем. Этот файл в репозиторий не входит.

Скетч заливают из Arduino IDE на плату «ESP32 Dev Module». Отдельная библиотека не нужна: Wire, Wi‑Fi и BluetoothSerial входят в ядро ESP32.

Пока датчик не ответил числом, в журнал ничего не пишется. Прошивка смотрит шину I²C и провод 1-Wire и сообщает, если там никто не ответил. Температуру из этого молчания она не выдумывает.

Опрос раз в десять секунд. Секундный интервал после росы включится вместе с чтением сенсора.

### USB

В `FVZ_LINK` оставляют `FVZ_LINK_USB`. Страницу запускают как обычно и в другом окне читают порт:

```sh
python3 station/line_in.py /dev/ttyUSB0
```

Порт может называться `/dev/ttyACM0`. Мост передаёт на страницу только строку показания. Фразу «на шине никто не ответил» он печатает у себя и в журнал не кладёт.

### Wi‑Fi

В `config.h` ставят `FVZ_LINK_WIFI`, имя сети и адрес компьютера, на котором открыта страница. Адрес `127.0.0.1` с платы указывает на саму плату, его писать нельзя.

```sh
FVZ_HOST=0.0.0.0 python3 station/server.py
```

`FVZ_URL` в прошивке тогда похож на `http://192.168.1.10:8321/api/readings`.

### Bluetooth

В `FVZ_LINK` ставят `FVZ_LINK_BLUETOOTH`. Плата объявляется как `Fermozavr-TRH`. Это последовательный профиль классического ESP32, не BLE. На ESP32-S3 и ESP32-C3 эта сборка не компилируется: у них такого профиля нет, остаются USB и Wi‑Fi.

Страницу наружу открывать не нужно. Ноутбук принимает ту же строку, что и с кабеля:

```sh
bluetoothctl pair AA:BB:CC:DD:EE:FF
sudo rfcomm bind 0 AA:BB:CC:DD:EE:FF 1
python3 station/line_in.py /dev/rfcomm0
```

`AA:BB:CC:DD:EE:FF` — адрес платы после сопряжения.

### Выводы

Назначение выводов ниже — для исходного ESP32. Это договорённость о пинах, не проверенная схема модулей: модулей на столе ещё нет.

| Сигнал | GPIO |
| --- | --- |
| I²C SDA, потом TCA9548A | 21 |
| I²C SCL | 22 |
| DS18B20 | 4 |
| MAX31865 CS | 5 |
| MAX31865 SCK | 18 |
| MAX31865 MISO | 19 |
| MAX31865 MOSI | 23 |

Pt100 через MAX31865 прошивка пока не опрашивает: у SPI нет отдельного ответа «я здесь». Сенсоры держат в 20–30 см от платы, потому что ESP32 греется.
